可信证书下的 Android 原生 H3 与生产回放（2026-11-16）

验证目的和范围
- 前轮 Android 15 / WebView 124 默认路径收到 Alt-Svc 但没有 H3，NetLog 显示自签证书不受系统信任。
- 本轮使用当前 Tailscale 节点的公开 CA 证书，检查 WebView 自行选择 H3 的能力。
  不添加强制 QUIC、SPKI 豁免、主机名映射或自定义根证书；只开启诊断 NetLog。
- 流量是 Android 模拟器经其 NAT 到 Linux runner 的 tailnet 地址。
  DNS 显式使用 Tailscale MagicDNS；并非公网直连、跨节点 tailnet、完整 Flutter 真机或线上 CF 实验。
- 原生 UA 和应用 UA 分别采集九种合成请求；负对照使用同域名的自签证书，要求原生拒绝且服务端应用请求为零。
- 生产回放额外执行 TLS/H2 两次采样，随后两个可信 origin 经生产 H3 状态机校准，
  由正式 HttpEgressClient 发出九种请求，比较方法、正文摘要、实际字段值及共同字段的 QPACK 表示。
  不声称任意请求头集合/顺序、任意并发、驱逐、导航、完整 TLS 随机分布或原始 QPACK 字节相同。

实现
- 诊断采集器显式加载当前节点域名、地址与 PEM 身份；配置仅允许 tailnet IPv4 和精确 ts.net 节点名。
  私钥和配置位于临时目录，产物目录不含这些文件；只上传 JSON、日志和驱动标准输出/错误。
- Android 可信模式在证书错误回调中取消请求；原 localhost 诊断模式保留既有行为，分别记录是否放行。
- 生产 H3 状态机不复制。原启动入口仍生成本地身份，诊断构建通过显式 API 注入证书与地址。
  发布构建不包含该诊断 API；常规生产监听地址和证书选择不变。
- 审计必须同时满足：正确目标的系统证书验证、原生无证书错误、没有豁免参数、完整同连接采样边界。
  缺失 NetLog、其他域名的证书验证、空请求、证书错误被放行或缺少场景均不能冒充通过。
- 工作流仅手动触发；构建和 SDK 准备完成后才加入节点；测试步骤十分钟、脚本六分钟硬上限。
  结束后立即登出，再上传证据；整个 job 最长三十五分钟，包含不占 tailnet 会话的构建。
- CSRF、Cookie、Origin、Referer 业务策略未改。BrowserStack 会话数为零。

结论与剩余范围
- 在已测版本和受控网络中，系统信任的证书足以让默认 WebView 经 Alt-Svc 使用 H3，
  正式 Core 采样状态机与回放也能通过比较。这支持此前对本地自签证书阻断默认 H3 的定位。
- 这不是正式 App 本地 H3 入口已修复：发布应用仍使用本地自签探针，未提供面向所有用户的可信入口。
  现有校准未就绪时保留 TLS/H2 的策略仍有必要。
- 本轮新增信任实验只跑 Android 模拟器；共享采样器改动适用于各平台，但不能代替其他平台复验。
  Windows 业务/独立 profile 差异、完整真机、iOS 本机 Core、蜂窝/Wi-Fi 切换和线上 CF 仍未闭环。

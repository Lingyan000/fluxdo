# 网络核心收尾状态

更新于 2026-11-06。本文件记录当前交付边界，早期方案草案不能替代验收结果。

## 本轮交付

- 常规 Dio 请求使用统一网络核心，包含 API、图片、上传及流式响应。
- DoH 查询合并、缓存刷新隔离、ECH 策略、连接复用及 HTTP/3 优化。
- 浏览器指纹采样、缓存及用户可主动选择的预置模板。
- 核心异常时的应急适配器、分阶段超时、取消和背压处理。
- 网络状态支持图形和普通分段列表；配置入口集中，重启进度与失败恢复可见。
- 图形连线仅表示配置关联，不是实时流量或完整的请求拓扑。

## 已知边界

- 原生音视频播放器尚未接入应用内网络核心，不自动使用应用内 DoH。
  本轮明确暂缓接入；没有引入媒体转发服务，也没有修改播放器插件。
- 图形/列表切换目前只保留在当前页面状态中，不作为持久化偏好。
- 核心运行状态不等于目标站点可达；预置指纹不保证免于 Cloudflare 挑战。
- 应急适配器的 DoH、代理、指纹能力不等同于正常核心路径。

## 后续验收

以下不作为本次合并的阻塞项，但完成前不宣称已达到性能极限或全平台长期稳定：

- Android 真机 Wi-Fi/蜂窝切换、弱网、休眠唤醒及长时间运行。
- 图片首字节/完成耗时分布，以及 CPU、内存和耗电对照。
- 已登录账号的登录恢复及上传场景，由人工验收。
- 各平台系统代理、证书、后台及长轮询行为。
- 显式启用真实网络核心与外网测试；普通测试默认跳过部分此类测试。

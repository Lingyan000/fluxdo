# 后台 WebView 复用

`SiteWebViewRuntime` 是同源后台 WebView 的实例所有者。HTTP 适配器、会话刷新和启动首页补水不再自行创建或销毁原生实例。

## 接入规则

- 不切换页面的 HTTP 请求申请共享租约，可以并发。请求 ID 由运行时分配，响应按 ID 分发。
- 导航、替换文档和会话刷新申请独占租约。队列按申请顺序调度，独占任务不会被后来的共享请求饿死。
- 租约必须覆盖整个任务及清理阶段。下载响应头返回不等于请求结束；二进制响应需等流结束、取消或空闲超时后再释放。
- 独占任务退出前恢复空白同源文档，清除页面脚本、定时器和桥状态。恢复失败时使实例失效，不交给下一个任务。
- 关闭一个 HTTP 适配器只关闭该调用者；强制关闭取消自己的任务，普通关闭允许在途请求结束。
- 无任务持续一分钟后回收实例，下次按需重建。账号会话代变化会使旧租约和排队任务失效，清理后重建页面。
- Windows 手动验证沿用现有 `EmbeddedBrowserControllerPool.suspendAndDrain()` 入口，同时排空后台运行时，并等待原生析构冷却。验证结束后恢复申请。

业务不能保留 controller 跨租约使用，也不能直接调用原生 WebView 的 dispose。证书策略、Environment、兼容脚本和初始 Cookie 灌入仍由统一配置提供。

CF 自动续期、登录页面、可见网页、帖子 iframe、UA 探测和 localhost 指纹采样仍有独立生命周期；不接入这个同源后台实例。

## 验证

租约队列测试覆盖并发初始化、独占公平性、等待取消、创建失败、会话变更、原生析构排空和空闲回收。适配器测试通过模拟控制器验证多个调用者共享、乱序响应、关闭隔离、二进制流租约及超时清理。

真实平台仍需检查 Windows 手动 CF 验证前后的恢复、各平台加载事件、首页补水和账号切换；单元测试无法验证原生 WebView 的实际内存占用及销毁时序。

真实 Chromium QUIC/H3 采集（2026-11-15）

结论与范围
本轮已实现受控回环 H3 采集器，实际运行 Chromium 99、110、156；尚未实现生产 H3 指纹回放。
不能把 H3 采集成功或已有 QUIC 连接能力描述为所有平台原生指纹已统一。
生产浏览器模板请求仍限制为 TCP/H2；普通无模板/DoH H3 策略保持原逻辑。

实现
core/net_core/examples/h3_fingerprint_probe.rs 启动临时 QUIC/H3 服务与 UDP 观测中继，
生成临时证书，使用独立 Chromium profile。只对该证书的 SPKI 使用命令行实验放行，
不修改系统信任库，不把证书忽略带进生产网络代码。
采集每条 UDP 流的 Initial 形态，通过 flow_id 关联 H3 SETTINGS、
关键流观察、QPACK 字段表示、请求 Priority。随机密钥和连接 ID 不作为固定模板值。
后续已修复连接关联：各 H3 请求对应同一 flow 的 Initial；见 linux-native-tls-20261115.txt。
旧报告仍保留首个 UDP 流的限制，不能把新采集能力追溯到历史数据。
观察器回调顺序不等于原始包到达顺序。完整 HPACK/QPACK 行为或字节等价不在验收内。
实验报告不输出私钥；浏览器 profile 和完整 netlog 不纳入分享证据包。

实际结果（最终采集器）
Chromium 99.0.4812.0：完成导航、fetch、done 三个 H3 请求。
  首航 Initial 1 包，1250 bytes，SCID 长度 0，packet number 长度 1。
  稳定 H3 SETTINGS 顺序：1=65536、6=262144、7=100，另有随机 GREASE。
  三个请求均无 Priority 头。
Chromium 110.0.5481.38：同样完成三个 H3 请求；本次首航 1 包，1250 bytes。
  稳定 SETTINGS 与本次 99 相同；三个请求均无 Priority 头。
Chromium 156.0.8078.79：完成三个 H3 请求；本次首航 2 包，各 1250 bytes。
  packet number 长度为 1、2；稳定 SETTINGS 多出 51=1（H3_DATAGRAM）。
  导航 Priority 为 u=0, i；fetch/done 为 u=1, i。
  具体 packet/CRYPTO 布局、GREASE、传输参数顺序见原始 JSON，不能硬编码成版本阈值。
三个版本都观察到 CRYPTO 分片/顺序变化：TLS 扩展不乱序，不代表 QUIC CRYPTO 布局不乱序。

证书负对照
同一个 Chromium 156、同样回环服务器，去掉 SPKI 放行：Initial 可采集，H3 请求数为 0。
服务端明确记录 CERTIFICATE_VERIFY_FAILED；不能仅凭超时就称为证书负对照通过。
采集器现在严格断言：正对照必须存在 /、/fetch、/done 的 HTTP/3 请求；
负对照必须无 H3 请求且有明确证书拒绝，否则进程返回失败。
这也说明该命令行实验不能直接等价于没有这些开关的 Android/iOS WebView 生产采样。

实验中发现并修复的采集器问题
- 最初默认 localhost 解析导致没有 UDP 样本；固定实验 DNS 到 127.0.0.1，保留失败记录。
- 现代 Chromium 会产生预连接，串行等待首条连接的请求使后续连接无人处理，出现 4 秒握手超时。
  netlog 与服务端错误保留；改成每连接并发处理后，156 导航/fetch/done 全部完成。
- UDP 中继原先只有一个全局 client 地址；改为每个浏览器 UDP 端口独立上游 socket，
  避免并发连接的回复串线。该修复限于实验采集器，不是应用线上路径的修复。

仍未完成
Apple/Android/Windows 原生 WebView 的 QUIC/H3 同类采样与完整回放；真实传输参数映射、
Initial 分片策略、QPACK 动态表与指令选择、恢复/0-RTT/Retry/迁移及网络回退全矩阵。
当前依赖有 Initial 捕获/编译、H3 SETTINGS/QPACK 限额/启动配置接口，不能据此声称闭环完成。
尚无证据证明上述 H3 差异是用户反复 CF 挑战的直接原因。

复现
cargo build --locked --manifest-path core/net_core/Cargo.toml --example h3_fingerprint_probe
core/net_core/target/debug/examples/h3_fingerprint_probe <Chromium路径> <全新输出目录>
core/net_core/target/debug/examples/h3_fingerprint_probe <Chromium路径> <另一全新目录> --without-spki
需要可运行的本地 Chromium 和回环 TCP/UDP 权限；输出目录不得含旧浏览器 profile。

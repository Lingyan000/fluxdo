跨平台生产 H2 优先级缺失
- Android Actions 43735277924（6aa12a4cbdc77ddf406a314851b668d98e18a790）原生 UA 的第二份采样

- Windows Actions 43735580048（b2be1c90a974cdee02b8c4e02c161313bc4d719a）则在恢复缓存后复现：
  当前 reference 依赖 0，磁盘缓存依赖 5，restored-core 没有优先级。

  保留 weight 与 is_exclusive。显式 priority 头、显式出站优先级及入站依赖继续优先；
  不复制采样旧流号，不宣称恢复任意浏览器依赖树。
- 真实 TLS/H2 线协议测试改为采入旧流 5，实发依赖 0、权重 219、排他标记 true；
  同时确认显式入站根依赖保留、非根入站流号不跨连接复制。测试通过。

产品边界和未完成项
- Windows 与 Android 的限定对照证明当前实测版本的原生报文能被生产 Core 回放；
  不能把 CI 的 QUIC/SPKI 调试选项当作正式应用默认路径已经启用或信任问题已经解决。
- Android 普通 user 系统不能使用上述调试命令行入口；默认本地 H3 采样需要另外解决可信入口。
  远程受信任采样端点需要可控域名和支持 UDP 的服务，目前没有可用入口，尚未部署。
- Windows 正式应用共享 WebView2 环境，尚未接入独立受限探针环境；没有修改全局证书校验。
- Android 在模拟器采样，Core 在 Linux runner 执行；Windows 原生采样和 Core 都在 Windows。
  前轮 iOS 为模拟器采样、macOS Core 回放；没有声称完整 Flutter 真机或 iOS 本机 Core 已通过。
- Initial 完整随机分布、任意并发/驱逐/导航、蜂窝与 Wi-Fi 切换、完整请求头集合/顺序和线上 CF 放行
  不在本轮通过范围。所有失败产物与修正后的离线复核分开保存。
- 本轮 BrowserStack 新会话 0，CSRF 与业务 Cookie/Origin/Referer 策略未改；PR 432 保持 Draft。

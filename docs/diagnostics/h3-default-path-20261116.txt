Windows 正式实现
- 从当前核心状态读取各 H3 端口对应的公开 SPKI，要求规范 Base64 且解码恰好 32 字节。
  缺失或非法指纹时不创建原生环境，也不退回共享环境放行证书。
- 每个探针使用独立临时 profile；参数仅指定 localhost 当前端口、当前 SPKI 和 IPv4 回环解析。
  不改业务 WebView 环境，不导入根证书，不使用全局 ignore-certificate-errors。
- QUIC 内部已知根豁免按主机判断；不能误称其本身也按端口隔离。这里用独立环境、精确 SPKI、
  当前端口导航限制和自有固定探针页共同限定范围；H3 证书回调一律拒绝再次兜底放行。
- TLS/H2 首次就绪仍可提前返回，独立 H3 校准在后台串行执行；主环境无需重建。
- 超时或取消后迟到的原生环境仍回收；已经取消时不会继续创建原生环境。

控制器创建和销毁顺序
- 本地 Windows 插件 HeadlessInAppWebView.run 在原生异步创建回调中才注册控制器并返回成功。
  Dart dispose 在 _running=false 时直接返回。原先 run 超时后立即 dispose 可能漏掉迟到控制器。
- 现在保留原始创建 Future，按创建结束、销毁控制器、销毁独立环境的顺序处理。
  调用方最多等待五秒清理，后台仍负责迟到结果，不提前释放创建中的环境。
- 创建失败仍回收资源；控制器销毁失败也执行环境释放，错误不会被当作采样成功。
- 原生文件锁短时间未释放时有界重试临时目录删除；仍占用时记录日志，不无限阻塞业务。

本地检查
- 独立环境与资源生命周期八项、原采样状态机十一项、架构守卫八项，共二十七项通过。
- 定向 Flutter 分析无问题。最小 Flutter 宿主也已单独分析。
- 新宿主逐字复制生产环境管理类并记录 SHA-256，使用项目内 Windows 插件；
  主 WebView 在探针运行期间保持存活，采样后验证主控制器仍可执行 JS、探针目录已移除。
  这不是完整 FluxDO Flutter 应用或实体用户设备的认证。
- 独立 profile 采到的是当前真实 WebView2 引擎；尚未证明它与业务 profile 的持久化实验配置完全一致。
  同版本与同 UA 不能单独证明全部 H3 策略一致，该边界不能用隔离环境的通过结果掩盖。

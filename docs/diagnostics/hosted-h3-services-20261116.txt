真实返回结果
1. BrowserLeaks — https://quic.browserleaks.com/
   第一次 navigation -2，第二次 HTTP/1.1，第三次 H3。不能因首次错误就判定服务不可用。
   H3 响应包含 JA4、13 个传输参数、5 个 SETTINGS，以及 SETTINGS/GREASE/PRIORITY_UPDATE/HEADERS。
   观察到一个 Initial，包长 1250、包号长度 1；frames 是整数类型列表，没有每个 CRYPTO
   帧的 offset/length。因此只有帧类型顺序，不能重建当前模板所需的完整分片布局。
   HEADERS 提供解码后的值，未提供本轮所需的 QPACK 指令/字段编码表示。

2. Scrapfly — https://quic.tools.scrapfly.io/api/fp/quic
   两次 H2 后第三次 H3。包含 QUIC 参数、TLS 扩展、SETTINGS，另有 reproduction 辅助字段。
   原始 initial_packets 的 packet_length=0、packet_number_length=0，不能作为有效布局导入。
   reproduction.initial_packet_size=1250 不能代替缺少的原始帧布局。
   本次 http3 只有 SETTINGS；没有请求字段编码和 QPACK 关键流过程。

3. Impersonate.pro — https://fp.impersonate.pro/api/http3
   两次 H2 后第三次 H3。包含 TLS 扩展、13 个 QUIC 参数、5 个 SETTINGS、请求头顺序和值。
   没有 Initial 包列表/CRYPTO 分片布局，没有 QPACK 编码过程。

- 三家最终响应都由 WebView 的 nextHopProtocol=h3 观测确认，不仅凭接口名称推断。
- 三家响应中的 User-Agent 均与宿主实际原生 UA 相同，SSL 错误均为 0。
- 以上缺口是本轮响应的实际观察，不是声称服务永远不可能增加字段。
- 每家仅取得一份完整 H3 响应，没有完成两条独立 H3 连接的完整校准。
  第二份样本可另行采集，但不能靠重复调用自动补出接口没有返回的 QPACK/CRYPTO 细节。

与当前 Core 模板的差距
- core/net_core/src/h3_template.rs 的 Sample 需要真实 ClientHello、Initial 分片/包号布局、
  有序原始传输参数、关键流/控制帧边界、逐字段 QPACK 表示，以及多轮稳定/值复用观测。
- 解码后的 headers 不等于编码时的索引、Huffman、插入、引用与动态表行为。
  SETTINGS_QPACK_MAX_TABLE_CAPACITY 只是能力参数，不能代表完整的 QPACK 策略。
- 不从不同服务、不同连接或不同 UA 的零散字段拼接成一个“真实浏览器模板”。
- 本轮没有把第三方接口接入正式应用。它们已证明适合继续做公网能力诊断和部分参数比对，
  尚未证明能够完整替换当前生产采样器；此时引入远端依赖不能解决完整模板问题。

本地兜底已验证的实际行为
- TLS/H2 仍通过 localhost 校准，不依赖三家远端服务，不要求用户部署设施。
- 本地 H3 就绪时使用当前进程的实测模板；缺失或校准失败时维持已验证 TLS/H2。
- 已有 TLS/H2 模板不会因 H3 探针异常或 H3 状态暂不可读而撤销；新增两项回归验证了这两点。
- 首次业务初始化只等待 TLS/H2，H3 后台独立进行；同代失败不循环重试。
  停止重启、模板代次或证书身份变化后允许新一轮本地校准。
- Core 无 H3 模板时，即使有缓存 Alt-Svc 也不会启动默认指纹 QUIC。
- 有 H3 能力但 UDP 不通时，TCP 不等待 UDP 超时；只竞速建连，不在两条连接重复发业务请求。
- Dart 正式采样回归 15 项、架构守卫 8 项，共 23 项通过；定向 analyze 无问题。
- Core client::h3::tests 12 项通过，包含真实 socket 的 UDP 黑洞/TCP 回退、模板门控、
  固定代理、reset 取消、连接复用与证书拒绝。最初筛选 http3::tests 命中 0 项，未计作通过；
  改用真实模块 client::h3::tests 后实际执行 12 项、全部成功。

跨平台边界与决定
- 本轮远端接口网络实测只覆盖 Android 15 / WebView 124，不冒充 iOS/macOS/Windows/Linux 复验。
- 本地回退状态机和 Core 门控是共用实现，已有各平台证据仍适用各自记录的版本与环境。
- iOS 15.5 真机本机 H3 已成功；Windows 的限定本地探针有成功证据，但不能外推所有业务 profile。
- Android 已测本地自签入口仍受 Chromium 的证书/Alt-Svc/QUIC 策略限制。
  本地稳定兜底目前是 TLS/H2，不宣称已经实现所有 Android 设备离线可用的 H3 校准。
- 已测 Linux libsoup 3.6.5 路径只有 H1/H2，不将原生不具备 H3 当成需要伪造模板的错误。
- 保持本地优先、远端可选。公开服务失败或字段不足时，不能阻塞启动、污染本地模板、
  将零值当实测、关闭证书验证，或要求维护者转而自部署。

更新：2026-11-06。网络、CI 工具链及主动模板选择已有分支提交；头像与 DNS 刷新修复已完成本地构建、单元及 FFI 回归，正在收尾发布 v0.2.30-beta.5。最新本地包为 `app-network-beta5-arm64.apk`，验证与发布边界见 [network-core-handoff.md](network-core-handoff.md) 文末。下文旧日期/旧包验证为历史记录。

## 已实现

| 项目 | 行为与资源约束 |
| --- | --- |
| DoH/ECH 建连流水线 | 地址就绪即开始 TCP，TLS 仍等待 ECH；保留既有备用握手与取消。新增地址、TCP、ECH 阶段日志。 |
| HTTP/3 | 接入锁定 Rama 的 QUIC/BoringSSL；认证 HTTPS 响应的同主机 Alt-Svc 触发后台建连，当前请求继续 H2/H1。全局最多 2 个探测，3 秒超时，失败退避 5 分钟；64 个替代服务记录，TTL 最长 24 小时。 |
| H3 安全与回退 | 沿用 DoH/ECH、平台证书验证与目标身份；TCP 代理路径不发直连 QUIC；不启用 0-RTT。失败连接淘汰，仅无请求体幂等请求允许既有的一次重试；POST/上传不自动重放。切网取消探测并关闭 endpoint，旧代际/旧端口不回填。 |
| H3 占用 | 两个地址族共享 endpoint；连接接收窗口 8 MiB、单流 2 MiB、发送窗口 2 MiB，最多 64 双向流、8 单向流，禁用 datagram，空闲 60 秒。最新源码：最多尝试两个不同地址，优先另一地址族，备用延迟 250ms；共享原有 3 秒探测总时限，不重放业务请求。旧测试包仍只尝试首个地址。 |
| 连接池 | 每客户端缓存最多 32 个连接身份，全局 64 个逻辑连接名额；H1 每主机 6 条。90 秒空闲回收在访问池时触发，淘汰不误伤仍在消费的 H2/H3 响应。TCP 地址竞速和备用握手可能临时使用多个 socket，64 不是物理 socket 总数上限。 |
| TLS 票据 | TCP 票据 AES-256-GCM 加密落盘，密钥存系统安全存储；最多 128 张、每身份 2 张、最长 24 小时，文件预算 512 KiB。按域名、端口、模板、ECH 和网络配置隔离；安全存储不可用时只用内存。不包含 QUIC 票据跨重启恢复。 |
| 图片落盘 | 后台最多 2 个写任务、8 MiB 编码字节预算；超大单图独占等待，排队满时向下载施加背压。保存/分享仍等待原子写入完成。 |
| 图片取消 | 共享下载按消费者计数；缓存内部监听不算视图。最后一个视图离开后宽限 250ms，其他视图/保存请求不受影响；已下载且剩余不超过 64KiB 的尾部允许写入缓存。 |
| 图片调度与解码 | 下载上限 content=6、小图共享池=12、sticker=3，总数仍为 21；头像与正文隔离，与表情公平共享小图池，静态头像最多 6 个、可能的动图头像最多 2 个；无头像时表情仍可用满 12 槽，正文保留一个前台名额；大图首帧解码最多 2 个、估算 RGBA 预算 32 MiB，超预算单图独占，小图旁路。保留首绘分帧和原有缓存容量；这些预算不是进程总内存上限。 |

H2 流控已核对 Rama 源码：`h2/client.rs` 回放 SETTINGS 优先于普通 builder 默认值，`streams/recv.rs` 与 `streams/streams.rs` 维护回放窗口与内部状态。本轮保留回放策略，没有根据 2/5 MiB 默认值盲目放大窗口。线上窗口/吞吐尚无充分对照数据，不宣称已证明最优。

HTTPS RR 的 h3 协议发现、跨主机 Alt-Svc、QUIC 0-RTT 未启用；HTTPS RR 继续用于既有 ECH/DNS 策略。TLS 文件采用 1 秒合并写入，崩溃窗口可能丢失最近更新；损坏/密钥不匹配时退回完整握手，不依赖持久化保证连接可用。

## 官方对照证据

样本是本地 LINUX DO iOS 1.0.4 build 9（macOS 包装），不是 Android APK。确认普通 CDN 图片进入 URLSession，linux.do 及子域进入自定义 curl；curl 配置启用 H1/H2/H3 Alt-Svc、TLS session load/save 接入 Keychain；图片具有消费者取消及部分重解码限流。不能由 curl 配置推断 CDN 实际使用 H3。

详见 [静态复核报告](network-research/official-ios-image-pipeline.md) 和 [关键指令证据](network-research/official-ios-image-evidence.txt)。报告中“当前 FluxDO”描述的是实施前快照；本文件描述实施后的行为。未复制官方 Int64.max 磁盘预算，也未为模拟其路由绕过用户 DoH 设置。

## 验证与边界

- Rust 66 项通过：真实本地 H3 两次大响应复用、无效证书拒绝、UDP 静默丢包退避/重置取消、TLS 加密票据重新加载恢复、TCP/ECH 重叠等。
- 图片针对性 34 项通过；11 个相关 Dart 文件静态检查无问题；`git diff --check` 通过。
- 完整网络回归得到 199 通过、3 个 Windows 用例跳过、6 个公网用例失败。失败均为公网 TLS 中断，系统 curl 访问同一 Cloudflare 目标也失败。不依赖公网的全量网络及真实本地 FFI 重跑：198 项通过、3 个 Windows 用例跳过。
- Android arm64 release 构建和模拟器覆盖安装/冷启动成功；首页、头像与匿名话题详情可见，核心正常启动；模拟器现有腾讯 DoH 配置下，主站和 ping 域名完成 H3 升级，H2 日志确认 ECH 接受。不能据建连日志推断所有图片请求都用 H3。
- 本机阿里 DoH 探针中，DoH 服务本身完成 H3 升级，但 CDN 和 Cloudflare 图片目标的 TLS 连接失败，不能给出有效 p50/p95。只读探针在 `core/net_core/examples/image_transport_probe.rs`，支持 `--doh` 和 HTTPS 图片 URL。
- 模拟器启动首页快照 PSS 266398 KiB / RSS 441680 KiB；旧包快照在不同话题页面，不能据此计算内存改善。没有完成同负载峰值 CPU/RSS、电量与真机首绘对照。

## 用户统一验收

安装上述新包，保留阿里云 DoH 配置，在常用网络下分别冷启动、连续浏览图片较多的话题、快速滚动后滚回、打开原图和保存，再对照关闭 DoH。若出现慢或失败，导出同一轮日志；其中连接协议、复用、ECH、阶段耗时与图片排队/解码记录用于区分原因。账号登录和上传按此前选择留待人工验收。

## 2026-11-05 后续源码完善（尚未打包）

- H3 双地址有界尝试：最多两个，优先 IPv4/IPv6 另一族；每客户端最多两个探测，因此最多四个探测握手。共享 endpoint，胜出/取消时丢弃其他 future，不产生重复 HTTP 请求。

## 2026-11-05 响应消费与跳转链

- Dio 5.11.1 项目内补丁将按需读取、取消和暂停计时延续到调用方，避免上层提前接收抵消核心背压。正常完成后解除共享取消令牌对响应闭包的引用。
- 重定向最多遵守调用方上限且不超过 10 跳；已知小响应最多排空 8 KiB/100ms，未知或大响应直接取消。不会为重放缓存整个流式上传；一次性流需由调用方明确重新发起。
- 每跳仅记录有限数值与域名，图片 connection 增加 connectionId。保持原下载并发与解码/落盘预算，未以增加并发补偿延迟。
- 头像标准尺寸修复已随本网络分支带入，减少非标准头像尺寸造成的额外 302。不能消除旧头像版本和存储迁移等服务端合理跳转。
- 最终本地网络/图片/头像 257 项通过，3 项 Windows 条件跳过；7 文件静态检查无问题。公共 Dio + 真实 FFI 验证了小响应跳转复用同一连接、延迟订阅和慢消费不误触超时。
- 与头像修复一起生成下一份测试 APK；具体产物、哈希与模拟器记录见 handoff 文档。本机验证未覆盖真机 p50/p95、CPU/RSS/电量、多平台发布和 30 分钟后台切网。

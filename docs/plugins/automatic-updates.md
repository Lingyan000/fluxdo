# 插件定时更新

入口：元宇宙 → 插件管理 → 菜单 → 插件自动更新；市场源页面也提供入口。

默认每天检查，可选关闭、每 6 小时、每天或每周。每个插件可单独排除；关闭总计划后，“立即检查”仍能查询和准备候选，但不会自动安装。单插件设置保存在宿主中，插件脚本不能修改。

## 来源与安装

只检查已启用市场源中、与原安装来源完全相同的插件 ID。不按名称匹配，也不从其他源接管同 ID 插件。文件安装和独立清单地址安装需要手动更新；从市场重新审阅安装后可以参与定时更新。

版本比较、宿主兼容性、HTTPS 下载、大小限制、SHA-256、清单身份、脚本和 RFW 校验复用市场安装流程。自动更新不安装相同版本与旧版本。下载完成的包放在宿主独立更新库，安装前重新校验摘要和清单，并刷新原市场目录核对渠道、版本及撤回状态；目录不可用时保留旧版。

实际访问范围未扩大且 SDK API 版本相同的更新可自动安装；减少域名、凭证路径或方法不要求重新授权，仍有效的凭证保留。扩大范围、改变发布者或无法证明兼容关系时进入“需要确认”，由安装审阅页面展示权限类别与具体范围。更新保留启用/停用状态、挂起原因、本地数据、服务凭证和用户的权限开关，不重新授予已关闭权限。

安装前及索引持久化后都核对原版本、来源、自动更新选择和使用状态。下载时发生卸载、换源、手动升级或关闭自动更新，迟到的结果不能重新安装。索引提交期间通过任务库的短租约暂停新任务领取，避免前后台交接运行旧代码。代码采用按摘要保存的独立文件；新索引提交失败或提交期间发现使用状态改变时继续读取旧代码。

## 时间与生命周期

- 桌面应用进程运行时按计划检查，休眠后在恢复时补查；应用退出后不承诺执行。
- Android/iOS 复用宿主现有系统唤醒任务，平台决定实际执行时间，频率不是精确定时保证。该功能无需插件的后台任务权限，也不会为更新单独启动前台常驻服务。
- 手机系统唤醒只检查并准备包，不修改安装索引。一次唤醒的更新时间预算为 22 秒，未完成的工作下次重试。
- 安装只在前台、插件没有打开的页面或可见卡片、没有交互弹层/未完成脚本事件/正在运行的任务时执行。保留的底栏页面可在更新设置中选择“重新加载插件并更新”；确认后释放实例，未保存输入会丢失。正在授权、付款或执行事件时继续等待，失败后页面重新绑定原版本。
- 原插件后台任务与更新共用唤醒注册；关闭其中一项不会取消另一项仍需要的系统任务。

计划、检查时间、重试时间和候选包持久化在 `metaverse_plugins/updates.sqlite`。事务租约避免多个引擎重复检查；进程退出留下的租约在 5 分钟后过期。失败从 15 分钟起指数退避，最多 6 小时，并遵守市场服务返回的冷却时间。回到前台不会无条件重新下载。

## 状态与验证

设置页展示上次/下次检查、待空闲安装、待确认、宿主不兼容及失败重试状态。“查看更新”进入市场详情和现有安装审阅流程。后台更新日志先保存在更新库，回前台后归档。更新日志标为 `plugin_update`，包含插件 ID、原版本、目标版本及结果，归属宿主框架。


## 版本恢复与数据迁移

每次切换以独立安装批次区分，代码文件按摘要保存。数据准备记录、升级前快照和迁移结果放在同一插件数据库中；正式索引提交后才应用候选数据。启动时先按已提交的批次完成或撤销准备记录，同一版本的备份恢复也遵循此规则。任务短租约阻止后台旧实例在切换期间继续写入。

只保留当前与上一版本代码及一份更新前数据快照。首次页面或卡片初始化事件成功表示启动检查通过；这不保证所有业务接口或页面均正常。引擎初始化失败或启动阶段触发执行限额时可恢复上一版并停用，用户确认后重新启用。初始化已经成功后发生的运行错误会暂停插件。管理页提供手动恢复上一版；恢复会丢弃更新后的本地修改，不会撤销任何服务端操作。

回退仍沿用用户已关闭的权限。如果上一版访问范围更大，自动恢复停止并要求在插件管理重新审阅。回退过的故障代码进入拒绝记录；自动更新在首次确认对应包摘要后跳过同一包，直到发布者提供不同产物。清空插件数据会清除快照与恢复历史，不能借回退找回已清空的数据。

清单声明 dataVersion 并要求 dataMigrations，缺省数据版本为 1。版本增加时触发 storage.migrate，参数为 {fromVersion,toVersion,scope}。迁移只能访问当前分区的普通存储与宿主能力列表，不得联网、授权、付款或访问凭证。共享区、遗留未归属数据和各账号分区分别迁移，scope 对应 shared、legacy 或 account，不能指定其他范围访问。全部成功后才发布；失败、容量超限或超时保留旧版本和旧数据。数据版本降低只能使用已有快照回退，不能直接把新数据交给旧代码。

显式存储通过 `storage.scopes` 和 `storage.default` 声明共享区和账号区，新增任务或通知不改变分区。扩大范围或改变默认分区需要用户审阅。未声明 storage 的旧插件继续按原来的任务、通知或论坛能力推导范围；包含多账号数据的插件须声明 `accountDataMigration`，注册 `storage.partition` 处理器，由插件解释旧数据中的账号字段。宿主不会猜测业务键属于哪个账号。

旧共享插件升级为仅有 shared 的显式清单时，普通键搬入独立共享区；账号分区保持隔离。升级后含 account 的插件不会把旧未归属数据公开到 shared。冲突拒绝覆盖；已采用显式范围的插件不能通过普通升级删除 storage 声明，回退需使用已有快照。

首次访问存储前，在独立引擎中传入 `{accountId, legacy, account}`：当前账号 ID、未分区数据和当前账号分区的副本，其他账号分区不会传入。此迁移需要已授予 `identity`；未授权时页面仍可启动，不能执行迁移。处理器只可调用 `host.features`、`crypto.sha256`，返回 `{legacy, account}`；不能联网、访问凭证、支付、操作界面或直接写存储。处理器应保留无法归属的数据，并拒绝冲突。正式运行实例只能读取自己的分区。

升级与备份恢复时，已有账号分区会逐个在隔离引擎整理，单次只传该分区，不依赖用户下次登录的顺序；整个结果随升级事务提交。首次访问存储触发的结果通过数据库快照比较后原子提交；并发变更时从新快照重试，账号变化或权限撤销时放弃。迁移标记按账号、脚本摘要和未分区数据摘要保存，成功后无需重复执行。`legacy` 中已消费的记录应移除，避免升级脚本后重复恢复。原升级快照用于回退；旧加密存档在清空插件数据前仍保留。未声明该能力的旧插件仅在可从凭证确定唯一账号时整体迁移；无法确定归属的数据保留且不暴露给页面。

## 备份与恢复

应用的数据备份包含插件清单、来源、发布者公钥指纹、普通数据、声明式偏好和自动更新选择。执行代码、服务凭证、定时任务租约和通知授权不导出。旧备份中的安装索引仅转成待恢复条目，不作为已安装代码执行。

导入后在插件管理的“恢复插件”查看队列。宿主从原启用的市场源重新下载稳定且兼容的包；文件安装要求重新选择文件，独立清单来源要求重新下载。不得用其他来源接管相同 ID 的备份。用户审阅后迁移数据、切换版本，并保持停用；恢复失败保留队列。发布者变化会在审阅中显示。账号授权需重新进行。

## 渠道与版本撤回

默认只接收 stable。启用测试版本后也可选择 preview，同一市场每个 ID 每个渠道至多一个条目。稳定渠道不得包含预发布 SemVer。撤回条目使用 withdrawn:true；将历史版本加入 withdrawnVersions 可以在提供修复版时提示已安装版本被撤回，reason 说明原因。

发布测试版本时，市场必须保留同一插件最近的正式版条目。默认市场仍展示正式版；开启测试渠道后才从两个渠道选择较新版本。关闭测试渠道不会把已安装的较新测试版降级。只有测试版且从未发布正式版的插件，可以只提供测试渠道条目。

撤回包不会自动或手动从目录安装；已安装版本不会被远程删除或无条件降级。用户可以停用、检查修复版或在本地审阅回退。渠道切换清除待安装候选并重新检查。目录错误与服务端冷却期间不安装缓存候选。

## 发布者信任

可选 publisher 字段使用 RSA-SHA256 签署规范化清单与两个资源的 SHA-256。RSA 密钥须为 2048–4096 位、指数 65537；签名覆盖插件 ID、版本、权限和资源内容。密钥指纹由规范化公钥计算。CLI 的 pack --key private.pem 和 market-entry --key private.pem 生成同一格式；私钥必须留在作者机器或发布服务的秘密存储中。

首次安装由用户选择信任来源和公钥，签名不表示平台已认证作者。已签名插件的自动更新必须延续相同公钥，或提供由原公钥签署的新公钥轮换证明（--previous-key old.pem）。丢失签名或未经证明的换钥要求重新审阅；换发布者视为换来源，清除旧业务数据及凭证。无签名插件仍可安装，自动更新依赖原市场来源与包摘要，界面明确显示未签名。

同一市场来源首次从无签名版本升级为签名版本时，需要用户确认公钥，原数据、凭证和权限选择保留。之后才使用该公钥判断作者连续性。

## 首次正式发行与开发数据

插件、SDK、CLI 与脚手架的首发产品版本从 1.0.0 开始。FluxDO 应用继续使用自己的版本序列；清单 schema、脚本 apiVersion、数据 dataVersion 各自描述协议兼容性，不随产品版本重编号。开发期发行包保留原标签、摘要与签名，首发使用独立标签，不覆盖旧产物。

已安装的较高开发版本不会自动降至 1.0.0。市场详情更多菜单提供同源版本切换和同版重装，重新下载、校验后进入完整安装审阅，明确显示当前与目标版本。只有插件 ID、原市场来源与签名发布者连续，且数据版本不降低时才保留数据、凭证、启用状态和权限选择；审阅期间安装身份变化会拒绝提交。无签名版本不能通过此入口保留数据降版。从文件覆盖市场版属于换源，会清除旧业务数据与凭证，不能代替同源版本切换。

首发市场候选只保留每个插件一个正式条目，移除同 ID 的高版本开发预览条目，防止客户端继续选择开发编号。候选包公开前不替换在线目录；草稿附件不可作为公开下载地址。

## 首页展示与处理入口

首页管理图标仅统计需要用户确认的更新和异常暂停插件，同一插件计一次。待空闲安装不会计入角标；管理列表直接提供更新审阅、异常日志和恢复运行入口。任务正在执行时才展示运行状态，声明后台权限不代表任务正在运行。

首页卡片的顺序与可见性独立于插件启用状态，隐藏不关闭底栏、链接和已授权任务。管理页仍能打开插件页面。新安装追加在末尾，卸载清理展示记录。数据备份包含展示偏好，恢复展示偏好不会恢复启用或授权。

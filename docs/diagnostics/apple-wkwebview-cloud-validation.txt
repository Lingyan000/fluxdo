本次样本中的 iOS 版本差异
同一第二轮 Mac 实例上，iOS 18.5 与 26.1 的原生样本存在以下差异：
- 26.1 的 SupportedGroups 和 key_share 增加 4588（X25519MLKEM768），key_share 长度 1216；
  18.5 的普通 X25519 key_share 为 32 字节，26.1 同时保留该项。
- SupportedVersions：18.5 含 TLS 1.3/1.2/1.1/1.0；26.1 为 TLS 1.3/1.2。
- TLS 1.3 套件顺序：18.5 为 4865,4866,4867；26.1 为 4866,4867,4865。
- H2 SETTINGS 顺序：18.5 为 [2,4,3]；26.1 为 [2,4,3,9]，新增 no_rfc7540_priorities=1。
- 两者伪头顺序相同，窗口更新增量均为 10485760。
这些是实际样本差异，不据此新增全局版本阈值；Core 按各自真实采样复现的字段均通过。

验证字段与边界
检查 TLS 套件、协议版本、扩展集合/排列策略、支持组、签名算法、ALPN/ALPS、
证书压缩、EC 格式、key_share 组别与长度、H2 初始帧/窗口/伪头、Accept-Encoding 和低熵 Client Hints。
每组还覆盖连续复用、连接池重置、四请求并发、磁盘模板恢复、响应超时后恢复。
不把随机密钥、GREASE 值、ECH 密文、padding 长度、PSK/cookie 和 ACK 时序当作稳定字段。
首轮未观察到 TLS 会话恢复，不把连接复用测试当成会话恢复验证。
没有验证 H3、完整 HPACK/HEADERS 优先级、真实出口变化、公网 DoH/ECH 或 Cloudflare 判断。
项目最低支持 iOS 15 / macOS 12，本次可用云端版本不覆盖全部受支持版本。

新发现：真实系统版本与 UA 版本不同
iOS 26.1 与 26.2 的原生 WKWebView 都返回 CPU iPhone OS 18_7。
按现有应用 UA 补齐规则，得到 Version/18.7，而非实际系统 26.x。
首轮这两个 iOS 版本的稳定 TLS/H2 字段相同，不能凭 UA 相同推断系统未升级。
这说明 UA 的系统字段不适合作为实际 iOS 版本来源；缓存失效判断也不应仅依赖该字段。
这是版本标识/缓存依据的后续改进点，不是本轮已证明的 CF 触发因果；当前未修改生产 UA 规则。
macOS 默认/应用 UA、iOS 26.2 默认/应用 UA 的稳定 TLS/H2 字段一致，低熵 Client Hints 均为空。
